Диагностика создания lab4, 18 октября 2026 года.

Повторный запуск kind выполнен с --retain и отдельным kubeconfig:
  /tmp/lab4-debug.kubeconfig
Полный вывод создания сохранён в:
  /tmp/lab4-kind-create.log

Обнаружено в журнале kubelet контейнера lab4-worker:
  Unable to read config path: unable to create inotify: too many open files
  Failed to start cAdvisor: inotify_init: too many open files
  kubelet.service: Main process exited, code=exited, status=1/FAILURE

Лимиты хоста при первом диагностическом замере:
  fs.inotify.max_user_instances = 128
  fs.inotify.max_user_watches = 65536

Повторное создание kind формально завершилось успешно, но на этом этапе
рабочая нода не зарегистрировалась в Kubernetes; kubelet перезапускался.
Была зарегистрирована только lab4-control-plane, Ready.

Временное исправление из документации kind (выполнить на хосте):
  sudo sysctl -w fs.inotify.max_user_instances=512 fs.inotify.max_user_watches=524288

Автоматически применить исправление не удалось: sudo потребовал интерактивной
аутентификации. Эта попытка не изменила лимиты. Настройки в /etc не записывались.

Последующая проверка после выполнения пользователем команды sysctl:
  fs.inotify.max_user_instances = 512
  fs.inotify.max_user_watches = 524288
Эти значения подтверждены как на хосте, так и внутри обеих нод.
  lab4-control-plane: Ready
  lab4-worker: Ready
Все системные поды Running и Ready.
В журнале kubelet появилась запись Successfully registered node для lab4-worker;
kubelet работает, повторное создание кластера не требуется.

Первоначальный пользовательский сбой виден только на неполном скриншоте.
Ошибка inotify подтверждена для диагностического повторного запуска.
Вывод sysctl -w показывает значения после записи, а не до изменения.

После повышения лимитов kubelet автоматически повторит запуск.
Для подключения стандартным kubectl:
  kind export kubeconfig --name lab4
Проверка регистрации и готовности обеих нод:
  kubectl --context kind-lab4 get nodes -w
После появления двух Ready выйти из просмотра через Ctrl+C и проверить поды:
  kubectl --context kind-lab4 get pods -A

Источник:
  https://kind.sigs.k8s.io/docs/user/known-issues/#pod-errors-due-to-too-many-open-files
